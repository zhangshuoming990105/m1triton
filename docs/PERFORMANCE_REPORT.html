4. DSL-Compiler Co-Design 核心剖析：未来提升从编译器、语言还是算子来？

从 210 个真实案例与 13 次正反实验（含 4 次回退教训）中提炼出的三层分工法则

The DSL-Compiler Co-Design Law
「算法创新留在算子层做一次，反复出现的硬件与数学结构约束沉淀为极简 DSL 契约 (tlx.*)，一切可从 TargetSpec 机械推导的调度、内存布局与融合全部下沉进纯 C++ 编译器 Pass。」

对 M1Triton 下一阶段演进的定量判断：约 45% 的剩余通用收益来自编译器 Pass/IR 升级（以多消费者/归约尾融合与 SRAM 活跃区间分析为代表）， 约 25% 来自 DSL 语言契约补齐（让前沿算子摆脱黑盒 C++ 模板、支持可组合原语）， 约 30% 来自算子算法与数据布局创新（单循环 FA2 Bwd、片上 Winograd F(4×4)、单遍 CE 与 W4 nibble 布局）。

① 编译器 Pass & IR 层~45% 通用红利

零算子重写 · 收益随模型数量线性放大
  • Reduction & Spatial-Window Epilogue 融合：扩展 EpilogueDAGAttr，在 Conv/GEMM 写回同时片上算 2×2 MaxPool 或累加 Norm 统计量（sum, sum_sq），直接攻克 L2 #43 (1.02x)、#11 (1.09x)、#17 (1.13x)、#19 (1.42x)。
  • 全算子 Occupancy + SRAM Live-Range Coloring：把 WelfordNorm 纳入 FusionOccupancyCostModelPass 拦截 L1 #36 的 17.25 KB 悬崖；对 L3-02 FA2 Bwd 做 SRAM 活跃区间分时复用，将占用压回 <16 KB 保 3 TGs/core。
  • 拆解黑盒 tlx.* 宏算子为通用循环降低：支持对标准 Triton for k: tl.dot + online_reduce 循环自动识别并生成流水线 SGMM，减少 C++ 专用 emitter 维护面。
  • 自动 MetalGraph ICB 捕获与 Split-K 决策：在 compile_backend.py（FX 分区器）自动捕获静态子图与分段 Winograd（消除 L2 #4/#17/#32/#46 60–113 次发射），实测 ICB 可提速 1.47x。
放错层的代价：把 occupancy 裁剪、bank swizzle、epilogue 融合留在算子层，会导致每个新算子都重踩一次 16 KB SRAM 悬崖（L1 #36 就是血泪教训）。

② DSL / 语言层 (tl + tlx)~25% 表达力杠杆

填补「编译器无法安全自动推断」的语义鸿沟
  • 代数与稀疏结构契约：扩展 tlx.structure 至 causal_band / block_sparse / linear_commutes_with_pool，让编译器 100% 安全地执行类似 L1 #15 (3.96x) 与 L2 #77 (421x) 的死块剪枝与代数重排。
  • 硬件资源意图声明 (tlx.sram_budget / tlx.occupancy_target)：把 Apple Silicon 特有的「保 3 TG/core 优先于双缓冲」表达为一等语言契约，驱动成本模型而非写死魔法数。
  • SIMD-group 协作与持久调度原语：补齐 tlx.subgroup_shuffle、tl.associative_scan、tlx.persistent_reduce，让 L3-08 Mamba、L3-06 LayerNorm Bwd、L3-09 MoE 用纯 Python Triton 可组合写出。
  • 多输出/原地别名契约：声明只读/原地写缓冲区契约，供 command_batch() 和 MetalGraph 精确消除保守内存屏障。
放错层的代价：把每个新算法直接做成一个黑盒 tlx.my_op(...) 宏指令，会退化成「带 Python 壳的手写算子库」，失去 Triton 的可组合性（如 L3-07 无法把 gather+dlogits 拼进 tlx.online_softmax）。

③ 算子 / 算法与布局层~30% 复杂度降维

数学降阶与硬件亲和数据排布，编译器无法凭空发明
  • 单循环 FlashAttention-2 反向 (L3-02)：把 BwdDKDV 与 BwdDQ 合并，消除一半 QKᵀ 与 exp 重算；保留已验证有效的 Causal 逆序发射防尾延迟。
  • 单遍 Logits→Loss+dLogits (L3-07) & 单读 LayerNorm 反向 (L3-06)：分别消除 [chunk_t, V] 的 2 次多余 DRAM 扫盘与 (x, dy) 的双倍读取。
  • 片上变换 Winograd F(4×4, 3×3) & 通道分块 RMSNorm：攻克 L1 #57/#71/#63（0.76x–0.89x）的 36-tile workspace 带宽墙与 L1 #36（0.66x）的 1 MB 步长 64 路 TLB 抖动。
  • 硬件亲和权重重排 (L3-10)：离线把 W4 nibble 交错排布成直接对齐 simdgroup_half8x8 寄存器 lane 的格式，榨干 LLM decode 带宽。
客观硬件边界：Apple M1 Max 的闭源 AMX 协处理器在规整稠密大矩阵（L1 #1 0.98x, #7 0.89x）上有固定优势；死磕最后 5% 性价比低，主战场应锁定 L2 融合与 L3 算法。

实证账本：来自 .audit/experiments.tsv & experiments_v2.tsv 的 13 次真实正反实验（含 4 次回退）
